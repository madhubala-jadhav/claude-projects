# S04 — Month-over-Month Comparison

**Frame name in Figma:** `04 — Month over Month`
**Page:** `01 Report`
**Frame size:** 1280 × 1000 — the expanded comparison section of `report.html`.

---

## Purpose

FR13 tells the user what is biggest. This screen tells them what **changed**, which is the
actual decision input: rent being the largest category is true every month and therefore
carries no information, while Transport rising 41% does.

## Requirements served

| ID | How |
|---|---|
| **US7** | This month vs last month, by category |
| **FR14** | ▲/▼ and % per category, including the new/gone/flat cases |
| **AC6** | A second month's report shows MoM % change per category vs the first |
| **NFR7** | The comparison reads a prior month's `summary.json`, which is never overwritten |
| **G3** | Month-over-month change is part of the monthly summary |

## Layout

### 1. Section header

`SectionHeader`: **"August 2026 vs July 2026"**, with `textStyle.caption` / `text.muted`
beneath: **"Compared against output/2026-07/summary.json, generated 1 Aug 2026."**

Naming the file matters. FR14's comparison is only as trustworthy as its source, and a user
who reruns July after correcting it needs to know which version they are looking at.

### 2. Headline change strip

Horizontal card, `surface.raised`, `radius.lg`, three cells separated by `border.subtle`:

| | August | July | Change |
|---|---|---|---|
| **Total spend** | ₹42,350.00 | ₹39,679.00 | `DeltaChip/up` **▲ 6.7%** (+₹2,671.00) |
| **Total income** | ₹65,000.00 | ₹65,000.00 | `DeltaChip/flat` **0.0%** |
| **Net** | +₹22,650.00 | +₹25,321.00 | `DeltaChip/down` **▼ 10.5%** (−₹2,671.00) |

Note the deliberate colour inversion: spend ▲ is `delta.up` (red), and net ▼ is also red,
because both are the bad direction. The chip's caret and sign carry the meaning; colour only
reinforces it (design-system §2.2).

### 3. Comparison table — the main content

Header on `surface.sunken`:
`CATEGORY · AUGUST · JULY · CHANGE · ` then a **diverging bar column** headed `MOVEMENT`.

Sorted by **absolute change**, not by amount — the point of this screen is movement.

| Category | August | July | Change | Movement (bar width) |
|---|---:|---:|---|---|
| Shopping | ₹2,100.00 | ₹0.00 | `DeltaChip/new` **NEW** (+₹2,100.00) | right, `chart.series.slot5`, hatched left cap — **100%** |
| Food & Dining | ₹14,400.00 | ₹12,800.00 | `DeltaChip/up` ▲ 12.5% (+₹1,600.00) | right, `delta.up` — 76% |
| Entertainment | ₹0.00 | ₹649.00 | `DeltaChip/gone` **GONE** (−₹649.00) | left, `text.muted` — 31% |
| Groceries | ₹5,820.00 | ₹6,340.00 | `DeltaChip/down` ▼ 8.2% (−₹520.00) | left, `delta.down` — 25% |
| Transport | ₹1,760.00 | ₹1,248.00 | `DeltaChip/up` ▲ 41.0% (+₹512.00) | right, `delta.up` — 24% |
| Uncategorized | ₹1,420.00 | ₹1,830.00 | `DeltaChip/down` ▼ 22.4% (−₹410.00) | left, `delta.down` — 20% |
| Utilities | ₹1,850.00 | ₹1,812.00 | `DeltaChip/up` ▲ 2.1% (+₹38.00) | right, hairline — 2% |
| Rent/Housing | ₹15,000.00 | ₹15,000.00 | `DeltaChip/flat` **0.0%** | no bar, centre tick only |
| **Total** | **₹42,350.00** | **₹39,679.00** | **▲ 6.7% (+₹2,671.00)** | |

Note that **Transport, the largest percentage move at ▲ 41.0%, is only the fifth largest
actual move.** That gap is the reason this screen exists and the reason it sorts by absolute
change rather than by percentage.

**The Movement column is a diverging bar chart, centred on a zero axis** drawn in
`chart.axis`, scaled to the largest absolute change (Shopping, ₹2,100.00 = 100% width). It is the one
place in the report where a second chart earns its space: percentage and absolute change
disagree constantly (Transport is +41% but only +₹512; Food is +12.5% but +₹1,600), and the
bar is what shows which one actually moved the total.

### 4. Interpretation line

Below the table, `surface.accentSubtle` panel, `textStyle.bodyLg`:

> **"You spent ₹2,671.00 more than in July. Most of that is a new Shopping category
> (+₹2,100.00) and Food & Dining (+₹1,600.00), partly offset by ₹649.00 less on
> Entertainment."**

Generated by a fixed rule — largest positive contributors until 70% of the **gross** increase
(₹4,250.00 across all rising categories) is explained, then the single largest offsetting
decrease — not by prose templating per category.
It carries no advice and no target, because NG1 rules out budgeting judgement. It reports.

### 5. The five `mom_status` cases, rendered

`DeltaChip` variants exist for every case FR14 can produce. A bare percentage cannot express
three of them, which is why `mom_status` is a field in the data model rather than a
derivation in the template.

| `mom_status` | Chip | Colour | When |
|---|---|---|---|
| `up` | ▲ 12.5% | `delta.up` | prior > 0, current > prior |
| `down` | ▼ 8.2% | `delta.down` | prior > 0, current < prior |
| `flat` | 0.0% | `delta.flat` | change rounds to 0.0% |
| `new` | NEW | `text.accent` on `surface.accentSubtle` | prior == 0, current > 0 — **not** "+∞%" |
| `gone` | GONE | `text.muted` on `surface.sunken` | prior > 0, current == 0 (EC6 keeps the row) |
| `unavailable` | — | `text.muted` | no prior month, or prior schema unreadable |

## States

### Empty — no prior month (`WARN-503`)

The entire section collapses to one card, `surface.sunken`, centred `EmptyState`:

> **This is your first month.**
> Run the tool again next month and this section will show what changed, by category.
> *Your July report will be kept at `output/2026-08/` — nothing is overwritten.*

Every `DeltaChip` in the S01 category table simultaneously renders as
`DeltaChip/unavailable` ("—"). A dash is honest; a "0.0%" would be a lie.

### Partial — comparison month is not the immediately preceding month

`HistoryStore.previous_month()` returns the most recent stored month, not strictly
`month − 1`. If July was skipped, the header reads **"August 2026 vs June 2026"** with a
`surface.warningSubtle` note: *"July 2026 has no report, so the comparison skips it."*

### Error — prior `summary.json` is unreadable or a newer schema

`surface.warningSubtle` note: *"The July report was created by a newer version of this tool
and could not be read. Comparison unavailable."* The rest of the report renders normally
(NFR3). The prior file is **never** rewritten or repaired in place.

### Loading
Not applicable — static document.

## Interaction notes

| Trigger | Behaviour |
|---|---|
| Click a row | Opens [S02](02-category-drilldown.md) for the **August** transactions of that category. July's transactions are not available — only its `summary.json` is stored, not its rows. The drill-down header says so. |
| Hover a movement bar | Tooltip: *"Food & Dining: +₹1,600.00 — 38% of this month's ₹4,250.00 gross increase."* |
| Sort control | `Button/Secondary` segmented: **By movement** (default) · **By amount** · **A–Z**. |
| Keyboard | Table rows are focusable and `Enter` drills down, same as S01. |
| Print | The movement bars print as filled/outlined bars around the zero axis, so direction survives greyscale. |
